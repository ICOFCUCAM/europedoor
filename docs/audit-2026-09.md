# Repository audit — September 2026

Done before any code changed, per the brief's §29. This is the state of the
repository as found, and the one architectural decision that follows from it.

## 1. Current stack

| | |
|---|---|
| Language | Python 3.11, **standard library only** |
| Runtime deps | **zero** |
| Build deps | none. `playwright` is dev-only, not committed |
| Framework | none — a purpose-built static generator, `tools/build.py` |
| Package manager | none. No `package.json`, no `requirements.txt` |
| Database | **none** |
| Auth | **none** |
| Styling | one hand-written stylesheet, 764 lines, 208 component classes |
| Client JS | 5 files, vanilla, no framework, no bundler |
| API | 4 static JSON documents built at deploy time |
| Deploy | Vercel, `buildCommand: python3 tools/build.py`, `outputDirectory: site` |
| CI | GitHub Actions, one workflow, 7 gates |
| Output | 988 HTML files, committed, CI fails if stale |

~12,000 lines of source. That is the whole system.

## 2. Existing architecture

```
data/*.json                 the source of truth, hand-written, validated
    │
tools/lib/data.py           load + validate; refuses bad data outright
    │
tools/lib/{pages,render,    68 page builders, ONE page shell, one URL module,
           urls,score,i18n} one scoring module, one string catalogue
    │
tools/build.py              → site/ (988 pages + 4 APIs + sitemap + headers)
    │
assets/js/*.js              5 progressive-enhancement scripts. Every page
                            works with JavaScript off
```

Four rules the whole build depends on, all enforced by checks:

1. **One page shell.** `render.page()` is the only function emitting `<html>`.
2. **`site/` is generated**, deleted every build, and committed. Editing it is
   work that disappears silently.
3. **No page ships its own `<style>` or `style=` attribute** — that is what
   lets the CSP run `style-src 'self'` with no `'unsafe-inline'`.
4. **No `rank`, `boost`, `featured` or `sponsored` column on a place.** The
   editorial wall is enforced by the absence of a field.

## 3. Existing functionality

Working today, all of it tested: the Atlas (country → region → destination →
place), experiences by category and kind, 17 curated journeys, a browser-side
journey planner with natural-language input and an honest refusal path,
whole-index search with accent folding, a map with 17 layers and a text
alternative, events by month, stories, themes, My Europe with collections and
a device-to-device transfer, the Europe Fund register, a public verification
board, and a published scoring method.

Brief §6's MVP list, measured: **11 of 12 items exist.** The missing one is
the admin CMS, and git is currently doing that job for committers.

## 4. Existing database

None, and this is the audit's central finding rather than an omission.

The dataset is 50 country files plus 7 shared files, validated on every build
by a schema in code that lists **every problem at once** rather than dying on
the first. It carries what a relational model would: hierarchy, cross-links in
both directions, per-claim provenance with source kind and an expiring
verification date, and derived confidence that **cannot be authored**.

`docs/technical-foundation.md` has the PostgreSQL/PostGIS model ready. It is
not built, and §"The trigger" says why.

## 5. Existing authentication

None. No accounts, no sessions, no cookies, no passwords, no third-party
identity. My Europe is `localStorage` and a copy-paste transfer.

This is a deliberate legal position, not a gap: **there is no incorporated
entity, so there is no data controller.** Collecting personal data with nobody
answerable for it is worse than not having accounts.

## 6. Existing integrations

**None.** Zero third-party origins in 988 pages — verified by a check, and
enforced by `default-src 'none'`. No analytics, no fonts CDN, no map tiles,
no image host, no error reporting.

## 7. Existing design system

One stylesheet, 208 classes, eleven type steps, one spacing scale, two
shadows. Brand Bible V1 applied: Atlantic green, limestone, terracotta,
charcoal, brass. The mark is drawn once, inline. Illustrations are generated
per slug with a motif from the place's own tagging.

Every component the brief's §15 lists exists as a class. WCAG 2.2 AA is
enforced in Chromium in both colour schemes on every build.

## 8. Technical debt

Honestly, and in order of severity:

1. **~~Security headers never reached production.~~ FIXED THIS SESSION.**
   `site/_headers` is Netlify/Cloudflare syntax; this deploys to **Vercel**,
   which ignores it. HSTS, `X-Content-Type-Options`, `Permissions-Policy`,
   `Cross-Origin-Opener-Policy` and `frame-ancestors` were absent from every
   response in production while the repository looked correct. Both files now
   derive from `render.HEADERS` and a check fails on drift.
2. **`docs/roadmap.md` was three sessions stale** — it claimed 8 journeys, 8
   stories, 23 checks and 204 assertions long after all four had moved.
   Rewritten, and it now points at generated documents instead of copying
   their numbers.
3. **Eight documents the brief names did not exist.** Written this session.
4. **No structured data.** Zero JSON-LD across 988 pages. The largest
   unblocked opportunity in the repository.
5. **No `og:image`.** Open Graph is title/description/type only.
6. **`README.md` is thin** — does not get a new engineer to a build.
7. **The dataset is the real debt**: 192 places against a 1,000 target, 9
   stories against 100, and 0 of 50 countries fact-checked. Published as such
   at `/sources/freshness` and in `docs/content-report.md`.

Notably **not** debt: no dead code, no unused dependencies (there are none),
no failing tests, no TODO markers, no duplicated shell, no inline styles.

## 9. Missing infrastructure

Against the brief: database, ORM, migrations, auth, RBAC, session store,
rate limiting, CSRF, background jobs, object storage, observability, error
tracking, staging environment, feature flags.

**Every one of them is downstream of the entity.** Not one is needed by
Phases 0–4, and each one added now is a bill and an attack surface bought
before there is anything to protect.

## 10. Recommended implementation sequence

**Recommendation: do not rewrite. Continue on this stack.**

The brief asks for Next.js + PostgreSQL + auth. That is the right destination
and the wrong next step, for four reasons the brief itself gives:

- *"Do not rewrite the whole application when a focused change is
  sufficient."*
- *"Every major dependency must have a reason."*
- *"Prioritize a working MVP over theoretical completeness"* — 11 of 12 MVP
  items already work.
- *"STOP and request approval before changing authentication
  architecture."*

A rewrite would cost weeks, would delete 1,471 machine-checked assertions and
389 browser checks, and would unblock **nothing**: every feature the new stack
enables is waiting on the entity, not on the framework.

So:

| | |
|---|---|
| **Now** | Phase 0 gaps (headers ✅, docs ✅, README), then structured data and `og:image` — the highest-value unblocked work |
| **Then** | itinerary editing; the dataset (places, stories, fact checks) |
| **On the entity** | Postgres and auth, per `docs/technical-foundation.md`, in that order |
